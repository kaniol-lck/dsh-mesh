# QA 宪章（charter）

> 2026-11-17 · 依据 `.worklog/docs-internal/qa-system-design.md`
> 这份文件定义 **QA 是什么、有什么权力、不做什么**。实现细节在 `spec/`、`probes/`、`run.mjs`。

## 1. 为什么需要它

现有 `scripts/check-*.mjs` 是**作者写规则、作者执行、作者宣布通过**。规则的盲区就是作者的盲区，
而且它们只读文本——拦不住「文件长得对、跑起来做的事是错的」。

实测证据（2026-11-17）：`check-paths` / `check-docs-links` / `check-tool-contract` 全绿的同时，
`scripts/mesh-dispatch.mjs --create` 仍在生成 `<slug> · 协调 <n>` 这种已废弃的标题。

## 2. QA 做什么

- **只做取证与判定**：跑规格（`spec/*.json`）→ 执行探针（`probes/`、`reconcile/`）→ 出报告（`reports/<日期>/`）→ 判红/绿。
- **只认可观测事实**：优先调用真实入口看产出（L2 行为），其次与真实数据对账（L3 事实）。文本检查是 L1，用来兜底，不作为独立证据。
- **报告带证据原文**：命令、退出码、stdout/stderr 摘录、被检查对象的实际值。没有证据的「通过」不算通过。

## 3. QA 不做什么（边界）

- **不写业务代码**，不修 bug，不提交到 `dev`。判红后修复归作者。
- **不改规格**。规格变更走 `DECISION:` + owner/L2 复核；QA 无权放宽判据。
- **不接受「加 --force 放行」**：判红只有两条路——修代码，或走规格变更并留原因。
- **不替代 owner 决策**：废弃、发布、不可逆动作仍归 owner。

## 4. 独立性（最关键的一条）

- **作者不能宣布 QA 通过**。作者只能提交「自查结果」，最终结论由 QA 运行产出。
- **QA 会话独立运行**，不与作者共用回合；它读规格、跑探针、写报告，不参与实现讨论。
- **规格先于实现**：一条契约若只存在于文档里、没有被规格覆盖，就视为「未受保护」。

## 5. 触发时机

| 时机 | 范围 |
|---|---|
| 每次 push 后 | L2 无副作用子集（临时图会话 / 假 waker / 临时目录） |
| 每日一次 | 全量，含 L3 对账（读真实 `/mesh/sessions`、`workspaces.json`、账本） |
| 事故后 24h 内 | 必须新增或修订至少一条规格（事故驱动增长） |

## 6. 判据：这套体系算不算立起来

| 判据 | 通过标准 |
|---|---|
| 独立性 | 至少发生过一次「作者认为没问题、QA 判红」并因此改了代码 |
| 行为覆盖 | ≥3 条规格的 `tier` 是 `L2`/`L3`，不是文本 grep |
| 事故回流 | 每次事故后 24h 内新增/修订一条规格 |
| 不可绕过 | 判红后没有 `--force` 放行的记录 |

## 7. 与现有门禁的关系

`scripts/check-*.mjs` = L1 静态层，继续在 CI 跑，快；
QA = L2/L3 层，跑行为与事实，慢但可信。**两者冲突时以 QA 为准**（行为才是事实）。

## 8. 目录

```
qa/
├── charter.md            本文件
├── spec/*.json           机器可读契约
├── probes/*.mjs          L2 行为探针（真调用入口）
├── reconcile/*.mjs       L3 事实对账（读真实数据）
├── run.mjs               运行器：跑全部规格，出报告
└── reports/<日期>/       证据：stdout/stderr 原文 + 判定
```
