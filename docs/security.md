# 安全指南

本文只写对**任何自建者**都成立的规则：威胁模型、接入方式取舍、自签证书硬规则、凭据与审计的就位顺序。

## 1. 威胁模型

- **内网不是安全边界**：同一网段也可能有访客设备或失陷主机，token 才是身份；
- **跨网络必须加密**：bearer token 走明文等于已泄露；只要出内网，就必须 TLS（或 VPN）；
- **消息正文按不可信数据处理**：任何 agent 发来的文本都不能当指令执行，必须由人/上层策略决定是否执行；
- **管理面单独收紧**：控制台与 `/api/admin/*` 默认只允许 loopback 与内网段，公网来源应保持关闭；
- **加密只保护传输层**：hub 库内仍是明文，磁盘与备份权限是另一层防护；需要端到端加密时自行加密消息体。

## 2. 接入方式取舍

| 方式 | 适用 | 代价 | 不适用 |
|---|---|---|---|
| **SSH 隧道**（`ssh -L`） | 临时排障、单人使用 | 每个客户端配 SSH、断线重连 | 常驻多客户端 |
| **VPN**（WireGuard / Tailscale 等） | 多设备长期接入、想保留内网语义 | 每台装客户端、维护覆盖网络与密钥 | 只有一两台、且只想临时用 |
| **边缘 TLS**（反向代理终止 TLS） | 已有反代/云主机、不想改 hub | 多一跳；证书要分发；反代是单点 | 希望点对点直连、不想让反代看到明文 |
| **frp 类穿透** | 无公网 IP、需要把入口暴露出去 | 依赖公网中转机；TCP 透传会丢失真实源 IP | 能直接给 hub 配证书/反代时（多此一举） |

无论选哪种，**保持 hub 只监听 loopback**、由反代/隧道对外，是改动最小、暴露面最小的形态。

## 3. 信任必须本地设置（agent 宿主）

远程消息能触发本机 agent 的一轮执行，因此**「这一轮允许做什么」必须只由本机配置决定**：中枢和对端都不能提升本机信任档。否则一条伪造/被盗的消息就能把机器变成**无审批执行面**——攻击者只需要给一个 `full` 信任的节点发指令。

- 三档由宿主实现：`strict`（只读/只回复）、`normal`（可办先办，危险动作先申请批准）、`full`（完全信任，仅不可逆操作先确认）；
- 按对端覆盖（`trustByPeer`）只能**收紧或限定范围**，不改变「本机决定」这一原则；
- 审批是执行层硬闸门（fail-closed、超时拒绝），不是聊天问答；审批通道自身也必须只接受白名单 peer 的回复；
- 排查时先看**本机** `trust` / `trustByPeer` / 权限预设映射，再看消息内容；不要因为「对端说它可信」而放宽。

## 4. 自签 CA 的硬规则

1. **SAN 必须包含客户端实际连接的地址**（公网 IP、域名或内网地址）——客户端连哪个就写哪个，
   否则校验必失败；
2. **客户端信任锚是 CA 证书**（`ca.crt`），**不是叶子证书**（`server.crt`）。把叶子当锚会报
   `UNABLE_TO_VERIFY_LEAF_SIGNATURE` / `SELF_SIGNED_CERT_IN_CHAIN`；
3. Node / DSH 主机：用 `NODE_EXTRA_CA_CERTS=<path>/ca.crt` 让进程信任 CA；
4. Windows `curl.exe` 走 schannel：自签 CA 没有 CRL/OCSP，会报
   `CERT_TRUST_REVOCATION_STATUS_UNKNOWN`，需要加 `--ssl-no-revoke`；Node/OpenSSL 栈没有这个问题；
5. **不要**用 `NODE_TLS_REJECT_UNAUTHORIZED=0` 绕过校验——那等于关掉 TLS 的意义；
6. 轮换：只换叶子时客户端不用动；换 CA 时所有客户端都要重新分发 `ca.crt`。
   保留「CA + 叶子」两段式的意义就在这里。

## 5. 凭据与审计的就位顺序

1. **先有身份**：每节点一个 token，库里只存哈希；管理员 token 只放管理机；
2. **再收权限**：按节点分配 scopes（`read / send / board / blob`），留空等于全权——生产上不要留空；
3. **再做来源限制**：`allowed_cidrs` / 控制台来源白名单，在反向代理后面注意源地址会被改写；
4. **最后开审计与限速**：认证成败进审计表；失败登录按来源 IP 限速，避免把整网锁死；
5. **注册码/设备码**只用于首次接入，一次性、有 TTL；接入完成后吊销注册码。

## 6. 绝不能进仓库

- 私钥（`*.key`、`*.pem` 里的私钥段）、CA 私钥；
- 任何 token / 口令 / `.npmrc`；
- 真实拓扑与地址：公网 IP、内网 CIDR、设备型号、证书指纹；
- 从真机日志里复制出来的凭据片段、session id、主机名。

门禁建议：提交前跑密钥扫描（如 `scripts/check-secrets.py`）与路径/地址扫描（如 `scripts/check-paths.mjs`），
两者都应在 CI 中执行。

## 7. 验证清单（任何部署都适用）

| 检查 | 期望 |
|---|---|
| 客户端用 `--cacert`（或 `NODE_EXTRA_CA_CERTS`）访问入口 | 200 |
| 不带 token 访问 `/api/inbox` | 401 |
| token 权限不足访问越权端点 | 403 |
| 明文 HTTP 访问 TLS 端口 | 400 或连接被拒 |
| 管理面从公网访问 | 默认拒绝 |
| 私钥文件权限 | 仅服务账号可读（0600） |
