# <项目名> 协作约定

<!-- workspace-template: v1 (2026-10-31) -->

> **怎么用**：复制本文件到目标项目根，命名为 `AGENTS.md`；把 `<项目名>`、`<角色列表>`、`<各角色负责的目录>` 换成实际值，并按真实角色增删小节。约定变更需项目 owner 批准后再改本文件。

本文件是多个 agent 会话在同一工作区协作的**唯一约定源**。会话开工先读它，冲突时以本文件为准。

## 目录与归属

| 路径 | 内容 | 允许改它的会话 |
|---|---|---|
| `<各角色负责的目录>` | 该目录的内容与边界 | `<角色>` |
| `<各角色负责的目录>` | … | … |
| `.worklog/` | 本地台账（不入库） | 任何会话可写自己的 todo |

**不允许**跨目录顺手改：需要别的目录时，让协调会话派给对应执行会话。

## 会话纪律

1. **cwd 必须是本仓根**（clone/检出目录），不要用包含多个仓库的上级目录，否则相对路径找不到文件。
2. 相对路径一律以本仓根为准。
3. 提交只 `git add` 自己负责的路径；commit message 写**为什么**，不要只写"更新"。
4. 不 `git push --force`；不提交凭据、token、`.npmrc`（用密钥/路径扫描脚本做门禁）。
5. 发版/部署等不可逆动作**必须先得到 owner 确认**。
6. 待办写 `.worklog/todo/<自己>.md`，叙事与决策写 `.worklog/WORKLOG.md`，整套 `.worklog/` 不入库。跨域条目必须写 `归属：<会话>`。
6.1 **做完即改账**：本轮完成某条 todo 的工作时，**必须同一轮**把它置 `状态：已完成`，并在正文补一行验收证据（commit / 通过数 / 验证命令）。不要留给协调会话事后补。改 todo 用**行级追加/替换**，禁止「读全文 → 改 → 写全文」（并发下会丢更新）；同一文件不要两个会话同时改。
7. 工作日志的格式与收尾检查见 `.worklog/README.md`。
8. 改完自己的 todo 跑 `node .worklog/bin/roadmap.mjs --write`；收尾 `--check` 必须退出 0。

## 缺陷回流（协调会话）

1. 只在有证据时触发：同类问题 ≥2 次 / 一次故障让既有约定失效 / 检查脚本反复卡同一处。
2. 动作：记 WORKLOG 一行 → 若是约定缺口，产出本文件的补丁（含证据行与收尾验证办法）。
3. 约定变更必须先报 owner 批准，批准后落盘、记 WORKLOG；禁止静默改约定。
4. 统计口径固定为 `node .worklog/bin/defects.mjs --scan --threshold 3`；同类 ≥3 条才标 `READY FOR PATCH` 并起草补丁。

## 跨边界契约（所有会话）

任何「一侧写、另一侧读」的东西都算契约：消息（发送方/消费方）、清单（包清单 / 宿主 loader）、文档（描述/实况）、关口（`gates.json` 胶囊/真实待办）、状态字段（API 输出/消费脚本）。

**单测只能证明你这一侧；另一侧必须真机或脚本对账。**

- **消息类**：真机断言「谁消费、谁看见、消费后状态」；
- **清单类**：用真实解析器验，不看文件内容；
- **文档类**：写完用脚本扫（死链、内部痕迹、版本号与代码一致），不靠"我读过"；
- **关口类**：`--check` 必须无「无匹配」WARN；新增待办不得让已达成关口回退（用 `match` 胶囊，不用 `feature:`）；
- **长期约束用 `check` 判据**（如「文档与代码一致」），不要写成一次性 todo；`check` 每次求值真跑命令，标完成后仍会因再次失真而变红。
- **状态字段类**：字段改了要同时验「写入方」与「读取方」，并在文档里写成稳定契约。

**证据格式**：结论后面附「哪条命令 / 哪次真机输出」，不接受"应该没问题"。

## 跨域发现（所有会话）

1. 同域问题写自己 todo；跨域但只需改文件时，只写一条 `归属：<会话>` 的 todo，派活由协调会话统一做。
2. 跨域只读核对可直接问对端，并在 todo 标「已直连确认」。
3. P0 / 安全 / 阻塞自己：立即上报协调会话。
4. 例外：对方唯一能解且卡住你时可直连，但必须抄送协调会话一行（问了什么、对方怎么回）。

## 自测与生产环境

测试口径：单元/集成测试默认用临时实例（临时端口 + 临时数据目录），不碰生产数据；端到端验收允许打生产环境，但必须：

1. **命名前缀**：测试创建的资源以 `selftest-` / `test-` 开头；
2. **当场清理**：测试结束立刻删除；
3. **登记一行**：在 `.worklog/WORKLOG.md` 记 `SELFTEST: <名> · <用途> · <结果>`；
4. **巡检兜底**：定期巡检列出残留测试资源，发现即清理。

## 决策路由（谁能拍板）

判据：**不越界**（只影响本会话产出，不改别人文件/对外契约/版本号）+ **不阻塞别人** + **可记录**。

1. **必须走协调会话**：阻塞型问题、约定/流程变更、版本号、凭据与轮换、发版与部署、跨会话排期。
2. **会话自行决定**：非阻塞且不越界的选择（测试形态、内部命名、日志字段顺序、单文件内重构、文案默认取值），做完写 `DECISION:` 行即可。
3. **可直问 owner**：必须 owner 拍板但不影响别人 —— 可直问，同时抄送协调会话一行。
4. **记录义务**：无论走哪条路，决定必须落一行到 `.worklog/WORKLOG.md`：
   `DECISION: <一句话决定> · <谁定的：owner / <会话>> · <YYYY-MM-DD> · <影响面>`。
5. **冲突处理**：以「时间较晚 + 已记录」为准，并由该会话抄送协调会话回写本文件/todo。

## 派活账本（协调会话维护）

协调会话每派一单，在 `.worklog/dispatch/queue.md` 记一行：编号 / 会话 / 任务 / 派出时间 / 期望产物 / 状态。

状态机：`dispatched` → `started` → `committed` → `deployed` → `done`。

核对规则：
1. 超过 30 分钟仍停在 `dispatched`/`started` 且会话活跃 → 直接问「卡在哪」，不许靠猜；
2. `committed` ≠ 可用：需要部署的单必须等到 `deployed`；
3. 派活前先查条目归属文件：`node .worklog/bin/roadmap.mjs --json` 里每条 `entries[]` 都带 `file` 与 `line`；派活正文写「改哪个文件的哪一条」，不要按"应该是谁负责"去猜。

执行会话不需要维护这个文件；`todo/<自己>.md` 与 commit 就是账本的证据来源。

## 唤醒协调会话

- 本机唤醒用本地注入（`node .worklog/bin/dispatch.mjs --wake --title "<项目> · coordinator" --file .worklog/dispatch/<主题>.txt`），不要绕消息中枢；
- 触发门槛（满足其一才叫）：P0 / 安全；需要 owner 决策；阻塞自己 ≥30 分钟；任务完成且结论会影响别人下一步；
- **不唤醒**：普通进度、「我做完了」、todo 更新、例行问答；
- 正文首行必须是 `[WAKE] <一句话摘要>`；一次任务最多叫一次；
- 回复不等于送达：单向投递不会自动回传，需要协调会话行动必须显式唤醒。

## 多会话派活

- 派活优先用带 `taskId` 的方式（工具或 `dispatch.mjs`），多单用同一 `batchId`，全部结束只回执一次；
- **回执是线索，产物才是证据**：收到 `status=completed` 必须核对产物（commit、测试数、接口行为）；
- 派活前先看目标会话忙不忙，忙则明确「这条会排队到下一轮」；
- 会话标题用 `<项目> · <角色>`，避免多个项目重名。
- **只有协调会话可以新建会话**。`mesh_dispatch` 工具带 `createIfMissing` 参数，任何会话在能力上都能建，但约定上**执行会话禁止使用它**：会话是全局资源（侧栏按工作区聚合、标题共享命名空间），随手新建会让会话数失控（本机曾到 231 个，`/mesh/sessions` 分页就是为此而加）。
  - 执行会话需要并行时：写一条 `归属：<协调会话>` 的 todo，或用 `mesh_ask` 提问，由协调会话决定建不建；
  - 执行会话可以派给**已存在**的会话（跨域直连），但必须抄送协调会话一行；
  - 协调会话建会话时，标题必须用 `<项目> · <角色>` 前缀，并在派活账本记一行。
