# spawn：派生专项会话

## 为什么

长上下文会**注意力稀释**、会**幻觉**；每次自动压缩都是不可逆的有损重写，会悄悄改变项目方向。
所以大主题不留在主线：派生一个只装这件事的会话，主线只保留「决策 + 验收 + 一句结论」。

判据（详见项目内 `.worklog/docs-internal/context-economics.md`，若存在）：
同一主题已连续 3 轮以上才见底 → 派生；主线开始忘记自己定的约束 → 先轮换，再考虑派生。

## 怎么用

```bash
node ~/.dsh/skills/spawn/scripts/spawn.mjs \
  --title "<专项标题>" \
  --brief <brief.md> \
  [--parent <sessionId>] [--cwd <仓库路径>] \
  [--role-card <角色卡路径>] [--report-dir <报告目录>] \
  [--task-prefix <前缀>] [--allow-nested] [--force] \
  [--apply] [--json]
```

- **默认 dry-run**：只打印计划（父会话、cwd、brief 字节数、在飞派生数），不建会话、不派单；
- `--apply` 才真正建会话 + 派首单；
- `--help` 零副作用。

### 参数

| 参数 | 默认 | 含义 |
|---|---|---|
| `--title` | 必填 | 新会话标题（≤60） |
| `--brief` | 必填 | 专项 brief 文件（空文件拒绝） |
| `--parent` | `$DSH_SESSION_ID` | 父会话 id，回执回到它 |
| `--cwd` | 当前目录 | 新会话工作目录 |
| `--role-card` | 自动探测 | 追加到 brief 首行的角色卡（相对 cwd 解析） |
| `--report-dir` | 自动探测 | 期望产物目录（只写进 brief 提示，不创建） |
| `--task-prefix` | `T` | taskId 前缀（跨区可用 `XJ`） |
| `--allow-nested` | 关 | 允许从派生会话再派生（默认只允许一层） |
| `--force` | 关 | 跳过并发上限（默认 3 个在飞，2 小时窗口） |

## brief 写什么

目标（一句话）/ 范围（改哪些、不改哪些）/ 约束（分支、门禁、不许动的东西）/ 期望产出（报告路径 + 结论格式）/ 需要 owner 决策的点。

## 边界（写进派生会话的角色卡里）

- 只交报告 + 回执，**不写父会话的 todo / WORKLOG**；
- 不改主干、不部署、不碰凭据（具体按目标仓 `AGENTS.md` 的分工）；
- 默认不再派生下一层。

## 注意

- 子会话**首回合排在父会话当前回合之后**才开跑（实测 20 秒到 5 分钟），**不是同步调用**；父会话继续干别的，回执到了再收。
- 父子关系登记在 `.worklog/dispatch/derived-sessions.jsonl`（审计用，2 小时窗口后才让出并发名额）。
- 新会话建好后要等它进 `/mesh/sessions` 索引（实测 6~10 秒）再投递，脚本已内置等待。
